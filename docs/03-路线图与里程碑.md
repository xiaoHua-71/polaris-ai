# 路线图与里程碑

## 排期原则

- **按依赖排，不按日期排**。每个里程碑只有在验收标准全部满足后才算完成。
- **一次只推进一个里程碑**。半成品模块比没有模块更难维护。
- **每个里程碑先有文档，再有代码**。文档可以很短，但必须写清楚：目标、官方做法、验收标准、边界。
- **不为了「功能看起来多」跳步**。M2 没跑通多轮记忆，不做 RAG。

## M0 · 项目骨架（已完成）

**目标**：项目能构建、能启动、有最小 Web 接口、有 git 基线。

**交付物**
- Spring Boot + Maven 工程，JDK 21
- `GET /api/hello`
- `contextLoads` 测试
- README、`.gitignore`、git 初始提交

**验收**
- `mvn test` 通过（2026-11-02）
- `/api/hello` 返回 `{"app":"polaris-ai","message":"Hello, Polaris!"}`（2026-11-02）

## M1 · 最小对话闭环（已完成）

**目标**：用 Spring AI 的 `ChatClient` 真调 DeepSeek，完成一次「HTTP 请求 → 模型回答 → HTTP 响应」。

**交付物**
- `spring-ai-starter-model-openai`
- `ChatClient` Bean（含默认系统提示词）
- `POST /api/chat`：`{message}` → `{content}`
- `application.yml` 的 provider 配置
- 模块文档 [10-对话基础](10-对话基础.md)

**验收**
- `mvn test` 通过
- 真机调用返回 HTTP 200 和中文回答（2026-11-03）
- 空 `message` 返回 HTTP 400（2026-11-03）

**明确没做**：多轮记忆、流式、工具、持久化、统一错误、鉴权。

---

## M2 · 多轮对话与记忆

**目标**：同一个会话里，模型能记住前文；记忆有明确的 token 预算与裁剪策略。

**要回答的问题**
- 会话标识用什么？`conversationId` 还是客户端传入的 `sessionId`？
- 记忆先放内存还是落库？如果落库，表结构是什么？
- Spring AI 的 `ChatMemory` / `MessageChatMemoryAdvisor` 在本版本里有哪些能力？
- 预算怎么算：固定消息条数，还是按 token 估算？超预算先丢谁？
- 工具调用消息与工具结果会不会被裁剪拆散？（实现工具后再验证）

**交付物**
- 记忆存储与装配
- 多轮接口（同一会话连续对话）
- 模块文档 `11-对话记忆.md`

**验收**
- 第一轮告诉模型「我叫 Alice」，第二轮问「我叫什么」，回答「Alice」
- 超预算时不会把请求撑爆；裁剪逻辑有测试覆盖
- 明确记录 token 估算口径和误差范围

**前置**：M1。

---

## M3 · 流式输出

**目标**：模型回答逐段返回，协议用 SSE；客户端断开时服务端有明确行为。

**要回答的问题**
- Spring AI 2.0.2 的流式 API 是什么形态（`Flux` / `StreamingChatModel` / `ChatClient.stream()`）？
- SSE 事件怎么设计：`delta` / `done` / `error` 分别带什么？
- 客户端断开后，模型调用是继续还是取消？资源怎么释放？
- 是否需要心跳？

**交付物**
- 流式对话接口
- 前端可消费的 SSE 契约（可以先用 curl 验证）
- 模块文档 `12-流式输出.md`

**验收**
- `curl -N` 能看到逐段输出
- 断开连接后服务端不泄漏线程 / 连接
- 错误路径返回可诊断的结构，而不是裸 500

**前置**：M1；与 M2 无强依赖，但通常先做 M2。

---

## M4 · 结构化输出与提示词

**目标**：让模型稳定输出可反序列化的结构，并在边界做校验。

**要回答的问题**
- 用 Spring AI 的 `BeanOutputConverter` / structured output，还是自己解析 JSON？
- 模型输出不合法时怎么办：重试、降级、还是报错？
- 提示词模板怎么管理：硬编码、资源文件、还是数据库？
- 结构化输出与流式能否同时用？

**交付物**
- 至少一个结构化接口（例如「抽取实体」或「返回固定字段」）
- 提示词模板管理方式
- 模块文档 `13-结构化输出与提示词.md`

**验收**
- 连续 N 次调用能稳定反序列化（N 与失败率写进验证记录）
- 非法输入 / 非法输出都有明确错误路径

**前置**：M1。

---

## M5 · 工具调用

**目标**：模型能按需调用后端能力，并跑通「请求工具 → 执行 → 回喂结果 → 生成最终回答」的循环。

**要回答的问题**
- Spring AI 2.0.2 的工具注册方式（`@Tool` / `ToolCallback`）和执行循环由谁驱动？
- 工具返回什么结构？异常怎么回给模型？
- 最大轮次、单次结果长度上限设多少？
- 副作用工具是否需要人工确认？Polaris 第一阶段是否引入？
- 工具调用与 M2 的记忆如何配合，避免消息配对断裂？

**交付物**
- 至少两个只读工具（如时间、简单查询）
- 轮次护栏与结果截断
- 模块文档 `14-工具调用.md`

**验收**
- 模型自主选择工具并给出基于工具结果的回答
- 达到轮次上限时行为可预期（报错或降级，写明）
- 工具异常不会拖垮整个对话

**前置**：M1、M2（强烈建议先有记忆）。

---

## M6 · RAG 基础链路

**目标**：走通「文档 → 切片 → 向量化 → 存储 → 检索 → 注入提示词 → 回答」的最小闭环。

**要回答的问题**
- Spring AI 的 ETL 组件在本版本里覆盖到哪一步？
- Embedding 用哪个模型？本地还是远程？维度是多少？
- 向量库选型：内存 / Redis / Milvus / pgvector？
- 检索结果怎么进 prompt：`QuestionAnswerAdvisor` 还是手工拼接？
- 如何证明「检索到的东西确实被用上了」？

**交付物**
- 一个知识库导入脚本或接口
- 一个最小检索问答接口
- 一个小型评估集（哪怕只有 10 条）与命中记录
- 模块文档 `20-RAG-概述.md`

**验收**
- 至少 10 条自建问题，记录命中率 / 召回位置（口径写清楚）
- 关闭检索时回答质量明显下降（做对照）

**前置**：M1；建议在 M2/M5 之后。

## M7 · MCP 客户端 / 服务端

**目标**：理解并落地 Spring AI 的 MCP 支持，至少完成一种角色。

**要回答的问题**
- 框架提供的是 MCP 客户端、服务端，还是两者都有？
- 传输方式有哪些（stdio / SSE / streamable HTTP）？本机怎么联调？
- MCP 工具与 M5 的本地工具在注册、执行、错误处理上有什么差异？
- 安全边界：能否让模型直接调用任意 MCP 服务？

**交付物**
- 一个可运行的 MCP 客户端或服务端示例
- 联调记录
- 模块文档 `30-MCP-客户端与服务端.md`

**验收**
- 能完成一次跨进程的工具调用或资源读取
- 失败路径（服务未启动、超时、协议错误）有记录

**前置**：M5。

---

## M8 · 可观测性与工程化

**目标**：让调用可诊断、成本可计算、失败可归类。

**范围**
- 统一错误响应（替换当前框架默认的 400/500 裸响应）
- 超时、重试、限流策略
- 每次调用的 token 用量与成本记录
- 结构化日志与关键指标
- 配置校验：缺 key、错 model、错 base-url 时尽早报错

**验收**
- 无 key / 错 key / 错 model 三种情况都有明确、可区分的错误信息
- 一次调用能查到：模型、耗时、输入/输出 token、成本
- 文档 `50-可观测性与工程化.md` 与实现一致

**前置**：M1（其余里程碑可并行推进，但收尾前完成）。

# 技术栈与版本

## 版本矩阵

| 组件 | 版本 | 依据 |
|---|---|---|
| JDK | 21.0.5 | 本机 `E:\Java\jdk-21.0.5`；`pom.xml` 声明 `java.version=21` |
| Spring Boot | 4.1.2 | `spring-boot-starter-parent` |
| Spring Framework | 7.0.10 | 启动日志实测（2026-11-03） |
| Spring AI | 2.0.2 | `spring-ai-bom` + `spring-ai-starter-model-openai` |
| OpenAI Java SDK | 4.80.0 | 无 key 调用时异常栈中出现 `openai-java-core-4.80.0.jar`（2026-11-03） |
| Maven | 3.6.3 | 本机实测可完成 `test` / `package` |
| 模型服务 | DeepSeek 官方 API | OpenAI 兼容协议，`https://api.deepseek.com` |
| 默认模型 | `deepseek-chat` | `application.yml`，已真机调用成功（2026-11-03） |

> 版本以 `pom.xml` 和启动日志为准。上表里的「依据」就是复查入口。

## 为什么是这套组合

### Spring AI 2.0.2

- 截至 2026-11-03，Maven 仓库中 Spring AI 的稳定线最新为 **2.0.2**；`2.1.0-M1` 是里程碑版本，不选。
- 2.0.2 属于 Spring AI 2.x，**依赖 Spring Boot 4.1.2**（从其 starter POM 的依赖可直接看到），因此 Boot 版本不是独立选择，而是被它对上的。
- 没有选 `1.1.8`（Spring AI 1.x 稳定线末版）：1.1.x 对应 Spring Boot 3.5.x，和 star 项目同代；新项目直接上 2.x，减少一次未来的大版本迁移。

### Spring Boot 4.1.2

- 与 Spring AI 2.0.2 的 starter 对齐，避免自己组合出未经上游验证的版本矩阵。
- Spring Boot 4 带来 Spring Framework 7；因此**不能把 Boot 3 的写法直接照搬**（模块拆分、部分 starter、测试依赖都可能有变化）。遇到差异以启动日志和官方迁移说明为准。

### DeepSeek（OpenAI 兼容）

- 复用 OpenAI 协议，不绑定特定厂商 SDK；只改 `base-url` 就能换到其他 OpenAI 兼容服务。
- **`base-url`、`model`、`api key` 必须一起匹配**。同一个模型在不同 provider 下的 model ID 可能不同；拿 A 家的 key 打 B 家的端点会直接 401。

当前配置（`application.yml`）：

| 配置 | 值 | 可覆盖环境变量 |
|---|---|---|
| `spring.ai.openai.api-key` | 空占位，必须由环境变量提供 | `DEEPSEEK_API_KEY` |
| `spring.ai.openai.base-url` | `https://api.deepseek.com` | `DEEPSEEK_BASE_URL` |
| `spring.ai.openai.chat.options.model` | `deepseek-chat` | `DEEPSEEK_MODEL` |
| `spring.ai.openai.chat.options.temperature` | `0.7` | 暂未提供环境变量覆盖 |

> 已实测（2026-11-03）：`base-url=https://api.deepseek.com`（不写 `/v1`）+ `model=deepseek-chat` + 真实 key，`POST /api/chat` 返回 HTTP 200 和中文回答。说明 Spring AI 2.0.2 的 URL 拼接方式与 DeepSeek 端点兼容。

## 升级清单

升级 Spring AI 或 Spring Boot 时，按这个顺序检查：

1. **BOM 和 starter 一起动**。只升 BOM、不升 `spring-ai-starter-model-openai` 的隐式版本，容易出现类不存在或自动装配失效。
2. **确认 Boot 大版本匹配**。Spring AI 2.0.2 对 Boot 4.1.2；跨大版本前先看官方兼容说明。
3. **核对 provider 三元组**：`base-url` / `model` / key 的来源是否仍然一致。
4. **重跑三条验证**：`mvn test`、`/api/hello`、一次真实 `/api/chat`。
5. **更新本文档的版本矩阵和 [06-风险与待验证](06-风险与待验证.md)**。
6. **检查旧结论**：文档里凡是写「官方不支持 / 没有 X」的句子，升级后都要重新确认版本前提。

## 本机环境注意事项

- 默认 `JAVA_HOME` 指向 JDK 11，直接跑 Maven 会报「不支持发行版 21」。构建前先：
  ```bash
  export JAVA_HOME=/e/Java/jdk-21.0.5
  ```
- E 盘路径出现在命令位置时可能被工具链拦截；写进 `JAVA_HOME` 环境变量没问题。
- Windows 终端里的中文可能按 GBK 发出。发中文 JSON 请求时，先写 UTF-8 文件，再用 `curl --data-binary @文件`。
- 启动过服务的端口，停止后要用 `netstat -ano | grep ':8103'` 确认没有残留监听进程。

# 开发与文档约定

## 工程结构

```
dev/polaris-ai
├── docs/                          # 设计文档（本目录）
├── src/main/java/com/xiaohua/polaris
│   ├── PolarisApplication.java
│   ├── chat/                      # 对话功能（按功能分包）
│   ├── config/                    # 显式配置
│   └── controller/                # 仅保留骨架期的 Hello
├── src/main/resources/application.yml
└── src/test/java/com/xiaohua/polaris
```

### 分包原则

- **按功能分包**，不按技术层分包。对话相关（Controller / DTO / Service）都在 `chat/` 下。
- 未来模块沿用同一方式：`memory/`、`tool/`、`rag/`、`mcp/`、`observability/`。
- 跨模块共享且真正通用的东西才放 `common/`；不要提前抽抽象。

## 接口约定

| 约定 | 做法 |
|---|---|
| 路径前缀 | `server.servlet.context-path=/api`，控制器里写资源路径（如 `/chat`） |
| 请求 / 响应 | 用 `record` 定义 DTO，字段少而明确 |
| 校验 | 在边界校验（空字符串、非法参数）；不替模型或数据库做无意义的防御 |
| 当前错误形态 | 框架默认错误响应。空 message → HTTP 400；模型调用异常 → HTTP 500。**尚未统一，M8 处理** |
| 时间 / 数字 | 不要在文档里编造延迟、token 数；实测后再写 |

> 与 star 项目不同，Polaris **暂不引入统一响应信封**。先让接口保持原生 HTTP 语义，等 M8 真正需要时再设计；避免「一开始就套壳，后面所有接口都被迫兼容」。

## 配置与密钥

- `application.yml` 只放**非敏感默认值**。
- API key 只从环境变量读取：`DEEPSEEK_API_KEY`。仓库里不出现真实 key。
- 可覆盖项：`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。
- 改 provider 时，**base-url / model / key 三者一起改**，并立即跑一次真实对话验证。
- 测试上下文里用假 key（见测试类的 `properties`），**单元测试不访问外网**。

## 测试策略

| 层级 | 做法 |
|---|---|
| 上下文测试 | `@SpringBootTest` + 假 key，验证 Bean 能装配 |
| 单元测试 | 纯逻辑（裁剪、参数解析、错误映射）优先，不 mock 框架 |
| 真实调用 | **手工 E2E**，结果写进 [05-当前实现与验证](05-当前实现与验证.md) |
| 回归 | 每个里程碑结束前至少跑一次 `mvn test` + 一次真实接口 |

**不要把真实模型调用塞进常规测试**：它会慢、要钱、受网络影响，而且输出不确定。

## git 约定

- 主分支：`master`。
- 提交前缀沿用现有习惯：
  - `init:` 初始骨架
  - `feat:` 新功能 / 新模块
  - `fix:` 修 bug
  - `docs:` 纯文档
  - `test:` 测试
  - `review:` 代码或文档复核
- 提交信息写「为什么」，不写「改了哪些文件」。
- 推送前确认工作区没有意外文件；`target/`、IDE 配置已在忽略列表中。

## 文档纪律

每个非平凡模块新建 `docs/<编号>-<模块名>.md`，按**固定五段式**写：

1. 这个模块治的是哪类病（通用问题定义，不先看本项目）
2. Spring AI 官方怎么做（**写清版本**、类名、能力边界）
3. 本项目怎么落地，以及为什么（自研必须写理由和备选方案）
4. 数据结构与流程（伪代码、步骤、配置表）
5. 边界、已知限制、踩过的坑（现象 → 原因 → 规避）

写作红线：

- 不贴大段实现代码；用 `路径:行号` 或 `类名#方法名` 引用。
- 不写「显而易见」的套话；要写校验的是什么、不校验会怎样。
- 没有实测的数字或结论，必须标 **待验证**，并写验证方法。
- 不把「当前版本没有」写成「框架没有」。
- 实现与文档冲突时，先判断谁错；设计变了就更新文档，并把旧设计为什么不成立记进「边界与坑」。

模板见 [templates/模块文档模板](templates/模块文档模板.md)。

## 本机运行约定

```bash
export JAVA_HOME=/e/Java/jdk-21.0.5
mvn -f D:/Project/AIProject/polaris-ai/dev/polaris-ai/pom.xml spring-boot:run
```

- 默认端口 `8103`，上下文 `/api`。
- 停止服务后检查：`netstat -ano | grep ':8103'`，避免残留进程继续服务旧代码。
- 中文请求体先落 UTF-8 文件，再 `curl --data-binary @文件`。
- 跑真实调用前确认 `DEEPSEEK_API_KEY` 在当前 shell 可见：`[ -n "$DEEPSEEK_API_KEY" ] && echo set`。

## 里程碑完成定义（DoD）

一个里程碑只有同时满足以下条件才算完成：

1. 验收标准逐条实测通过，结果写进验证记录。
2. `mvn test` 全绿。
3. 对应模块文档写完，索引状态从 ⬜ 改为 ✅。
4. 已知缺口和「没做什么」写进文档，不留口头承诺。
5. 版本 / 配置变更同步到 [02-技术栈与版本](02-技术栈与版本.md)。

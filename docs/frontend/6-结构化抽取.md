# 6 · 结构化抽取对接（M4）

> 执行对象：前端仓库 `D:\Project\AIProject\polaris-ai\dev\polaris-ai-front`
> 契约版本：M4，2026-11-16。后端已实现并经 DeepSeek 实测。

## 6.1 目标

新增「结构化抽取」页面：用户输入一段文本，后端返回固定字段的 JSON，前端以表单 / 卡片展示。

这个接口**无记忆**：不需要 `conversationId`，每次请求独立。

**非目标**：抽取字段的可编辑修正、批量导入、结果持久化。

## 6.2 接口

`POST /api/chat/extract`

请求：

```json
{"message":"张三今年30岁，在杭州做后端工程师。"}
```

响应（HTTP 200）：

```json
{"name":"张三","age":30,"city":"杭州","occupation":"后端工程师"}
```

字段：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 文本中明确出现的人名 |
| `age` | number | 是 | 明确出现的年龄 |
| `city` | string | 是 | 明确出现的城市 |
| `occupation` | string | 是 | 明确出现的职业 |

缺失信息返回 `null`，模型不应编造（但无法强制保证）。

错误：

| 场景 | HTTP | 前端处理 |
|---|---|---|
| `message` 为空 / 超过 2000 字符 | 400 | 展示「输入不能为空或过长」 |
| 模型输出无法解析，或所有字段为空 | 422 | 展示「模型输出无法解析或未抽取到字段」 |
| 模型调用异常 | 500 | 展示通用请求失败 |

> 响应体是 Spring 默认错误体，`error` 字段只有 `Bad Request` / `Unprocessable Content`，**不要把英文短语直接展示给用户**；按状态码映射中文提示。

## 6.3 前端改造

1. `src/types/api.ts` 增加 `ExtractRequest`、`ExtractedPerson`。
2. `src/api/chat.ts` 增加 `postExtract()`。
3. 新增 `src/pages/ExtractPage.tsx`：
   - 文本域 + 示例按钮 + 「抽取」按钮；
   - 加载时按钮 `loading`；
   - 成功后用 `Descriptions` 展示四个字段，`null` 显示「未提取」；
   - 同时展示格式化后的原始 JSON，便于核对；
   - 422 / 400 映射为中文提示。
4. `src/App.tsx` 增加 `/extract` 路由；`AppShell` 导航增加「结构化抽取」。

## 6.5 curl 自测

```bash
printf '{"message":"张三今年30岁，在杭州做后端工程师。"}' > /tmp/extract.json
curl -X POST http://localhost:8103/api/chat/extract \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/extract.json

printf '{"message":"周末和朋友去爬山了。"}' > /tmp/extract-empty.json
curl -i -X POST http://localhost:8103/api/chat/extract \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/extract-empty.json
# 预期 HTTP 422
```

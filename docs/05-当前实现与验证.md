## 接口

### `GET /api/hello`

连通性检查，不依赖模型。

```bash
curl http://localhost:8103/api/hello
```

```json
{"app":"polaris-ai","message":"Hello, Polaris!"}
```

### `POST /api/chat`

多轮对话。同一个 `conversationId` 共享记忆；记忆窗口最多 20 条消息，超限由 `MessageWindowChatMemory` 裁剪。

请求：

```json
{"message":"我叫 Alice，请记住","conversationId":"11111111-1111-1111-1111-111111111111"}
```

响应：

```json
{"content":"你好，Alice！很高兴认识你。"}
```

错误：

- `message` 为空 → HTTP 400。
- `conversationId` 为空或超过 64 字符 → HTTP 400。
- 模型调用或数据库异常 → HTTP 500。
- 400/500 的响应体都是框架默认格式，**不含具体原因**（`server.error.include-message=never`）：
  ```json
  {"timestamp":"2026-11-07T04:26:47.724Z","status":400,"error":"Bad Request","path":"/api/chat"}
  ```

### `POST /api/chat/stream`

流式对话，SSE。请求体与 `/chat` 相同，校验规则相同；同一 `conversationId` 与同步接口共享记忆。

```bash
printf '{"message":"用三句话介绍你自己","conversationId":"11111111-1111-1111-1111-111111111111"}' > /tmp/polaris-stream.json
curl -N -X POST http://localhost:8103/api/chat/stream \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-stream.json
```

事件：

```
event:delta
data:{"content":"我是"}

event:delta
data:{"content":" Polaris"}

event:done
data:{"conversationId":"11111111-1111-1111-1111-111111111111"}
```

- `delta`：`{"content":"片段"}`，每个非空增量一条。
- `done`：`{"conversationId":"..."}`，正常结束。
- `error`：`{"message":"模型调用失败：..."}`，上游失败。流已开始，HTTP 状态仍是 200。
- 参数不合法 → 流开始前返回 HTTP 400。
- 客户端断开 → 服务端发送失败，取消上游模型调用；已生成的部分回答不写入记忆。

### `POST /api/chat/extract`

结构化抽取：从文本中抽取人物信息。**无记忆**，每次请求独立。

```bash
printf '{"message":"张三今年30岁，在杭州做后端工程师。"}' > /tmp/polaris-extract.json
curl -X POST http://localhost:8103/api/chat/extract \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-extract.json
```

响应：

```json
{"name":"张三","age":30,"city":"杭州","occupation":"后端工程师"}
```

- 缺失字段返回 `null`；不允许编造（提示词约束，无法强制保证）。
- `message` 为空或超过 2000 字符 → HTTP 400。
- 模型输出无法反序列化，或转换后所有字段为空 → HTTP 422。
- 错误响应体仍是框架默认格式，不含具体原因；原始输出只在服务端 DEBUG 日志中。
- 模型调用异常（401 / 网络 / 超时）→ 当前仍是 HTTP 500，M8 统一。

### `POST /api/chat/tools`

带工具的多轮对话。请求体与 `/api/chat` 相同；工具循环由框架驱动。

```bash
printf '{"message":"现在上海几点了？顺便算一下 (12+3)*4。","conversationId":"22222222-2222-2222-2222-222222222222"}' > /tmp/polaris-tools.json
curl -X POST http://localhost:8103/api/chat/tools \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-tools.json
```

响应：`{"content":"现在是上海时间……；(12+3)*4 = 60。"}`

- 可用工具：`getCurrentTime(zoneId?)`、`calculate(expression)`。
- 工具异常默认降级为错误文本回给模型，HTTP 仍是 200。
- 轮次超限（默认单工具 3 次、单轮总 5 次）配置为 `RETURN_ERROR_RESPONSE`：模型在回答中说明，不报 500。
- 记忆与 `/chat` 共享同一 `conversationId` 空间；工具中间消息不落库。

### `POST /api/rag/chat`

RAG 检索问答。**无多轮记忆**；启动时把 `src/main/resources/knowledge/*.md` 切片并写入内存向量库。

```bash
printf '{"message":"RAG 的 topK 默认是多少？"}' > /tmp/polaris-rag.json
curl -X POST http://localhost:8103/api/rag/chat \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-rag.json
```

响应：

```json
{"content":"4","sources":[{"source":"polaris-tools.md","title":"...","chunkIndex":3,"score":0.605}]}
```

- `sources` 来自 `QuestionAnswerAdvisor.RETRIEVED_DOCUMENTS`，按相似度降序，最多 `topK` 条。
- `message` 为空或超过 2000 字符 → HTTP 400。
- 本地模型文件缺失时**启动失败**（知识库初始化抛异常），不会静默降级成「没有知识库」。
- 模型调用异常 → 当前仍是 HTTP 500，M8 统一。

## 实现要点

- `config/ChatClientConfig`：构建两个 `ChatClient`：
  - `chatClient`：默认系统提示词、`TraceAdvisor`、`MessageChatMemoryAdvisor`、`PromptTraceAdvisor`；
  - `structuredChatClient`：抽取用，无记忆，`TraceAdvisor` + `PromptTraceAdvisor`，模板渲染器改为 `<>` 分隔符的 `StTemplateRenderer`。
  - `ChatClient.Builder` 是 prototype 作用域，两个 Bean 各拿一份，互不影响；控制器按 Bean 名用 `@Qualifier` 注入。
  - `ChatMemory` 使用 `MessageWindowChatMemory`（默认 20 条），底层仓库为 `JdbcChatMemoryRepository`。
- `observability/TraceAdvisor`：外层链路 Advisor，order 为 `HIGHEST_PRECEDENCE + 150`。同步/流式都输出「模型调用开始 / 模型响应」，记录端到端耗时、finishReason、model、token 用量；流式额外记录首 token 延迟、块数，取消单独记一条。
- `observability/PromptTraceAdvisor`：内层 Advisor，order 为 `HIGHEST_PRECEDENCE + 250`，只在记忆注入完成后打印「最终 prompt」，用于区分卡在记忆层还是模型层。
- `memory/JdbcChatMemoryRepository`：读/写记忆各输出一条 DEBUG 日志（conversationId、条数、耗时），直接定位数据库阶段。详情见 [15-自定义Advisor](15-自定义Advisor.md)。
- `chat/ChatController`：校验 `message` / `conversationId`，通过 advisor 参数 `ChatMemory.CONVERSATION_ID` 指定会话。
- `chat/ChatController#stream`：`ChatClient.stream().content()` 拿到 `Flux<String>`，逐片写成 SSE `delta`；正常结束发 `done`，异常发 `error`。`SseEmitter` 超时 120 秒；发送失败（客户端断开）时取消上游订阅。
- 流式记忆依赖 `MessageChatMemoryAdvisor` 的聚合：只有流正常完成才保存 ASSISTANT 消息。
- 序列化使用 Spring Boot 4 自动装配的 Jackson 3（`tools.jackson.databind.ObjectMapper`），不是 Jackson 2。
- `memory/JdbcChatMemoryRepository`：`saveAll` 在一个事务内先删后批量插入，符合接口的「替换整组消息」语义；按 `id` 升序还原消息顺序。
- 消息类型只持久化 USER / ASSISTANT / SYSTEM；遇到 TOOL 直接抛异常，留到 M5。
- 建表不自动执行：启动前手工运行 `sql/schema.sql`。
- `chat/ChatExtractController`：`call().content()` 拿到原始输出后，用 `BeanOutputConverter<ExtractedPerson>` 手动反序列化；`JacksonException` → 422，模型调用异常不拦截（→ 500）。之所以不用 `entity()`，是为了在转换失败时记录原始输出，且能精确区分这两类异常。
- `prompts/extract-person.st`：占位符 `<text>` 与 `<format>`；`<format>` 传入 `converter.getFormat()` 生成的格式指令。模板文件用 `<>` 分隔符，避免与 JSON 花括号冲突。
- `tool/ToolRegistry`：启动时收集所有 `@ToolGroup` Bean，用 `MethodToolCallbackProvider` 扫描 `@Tool` 方法，逐个包一层 `TruncatingToolCallback`（2000 字符），按分组建索引。
- `config/ToolConfig`：按 `polaris.tools.groups` 从注册器选出回调，暴露单个 `ToolCallbackProvider`；留空加载全部分组，未知分组启动即失败。
- `tool/TimeTools`：`getCurrentTime` 接受 IANA 时区，空值默认 `Asia/Shanghai`；非法时区抛 `DateTimeException`。
- `tool/CalculatorTools`：`calculate` 用 SpEL `SimpleEvaluationContext`，并做字符白名单（数字、括号、小数点、空格、`+ - * /`）与 200 字符长度限制。
- `toolChatClient`：带记忆 + `ToolCallbackProvider`；工具循环由自动装配的 `ToolCallingAdvisor` 驱动，order 为 `HIGHEST_PRECEDENCE + 300`，位于 `PromptTraceAdvisor`（+250）内层。
- 工具异常沿用默认 `ToolExecutionExceptionProcessor`（`alwaysThrow=false`）：异常转成错误文本回给模型，对话继续。
- `rag/RagConfig`：`SimpleVectorStore`（内存）+ `QuestionAnswerAdvisor`（topK / threshold 可配）+ 独立 `ragChatClient`。RAG 接口不带记忆 Advisor，避免历史问题干扰检索评估。
- `rag/RagKnowledgeBase`：启动时读取 `classpath:knowledge/*.md`，`MarkdownDocumentReader` 转 `Document`（补 `source`），`TokenTextSplitter`（`chunk-size=200`）切片并补 `chunkIndex`，最后写入向量库；无资源或全空时启动失败。
- `rag/RagController`：`call().chatClientResponse()` 取回答与响应上下文；从 `qa_retrieved_documents` 读取命中文档，映射为 `sources`（source / title / chunkIndex / score）。
- 本地嵌入：`TransformersEmbeddingModel`（ONNX Runtime 1.20.0 + DJL HuggingFace tokenizer），模型为 `bge-small-zh-v1.5`（512 维）。`pom.xml` 固定 onnxruntime 1.20.0（1.21.1 在本机 JDK 21 下 DLL 初始化失败），并排除 `ai.djl.pytorch:pytorch-engine`（避免无用的大体积原生库）。
- 测试策略：默认测试用桩 `EmbeddingModel`，`PolarisApplicationTests` 通过 `polaris.rag.enabled=false` + `spring.ai.model.embedding=none` 屏蔽真实模型；真实 ONNX 的冒烟与 10 条 Hit@4 评估由 `RAG_SMOKE=true` 手动触发。

## 已知缺口

按重要性排列：

1. **无统一错误**：同步接口的 401 / 超时 / 参数错误仍被折叠成 400/500 裸响应；流式接口虽有 `error` 事件，但错误码、分类和可重试性都未统一。
2. **无鉴权**：知道 `conversationId` 就能读写该会话；ID 不是安全边界。
3. **记忆无 TTL / 清理**：单会话最多 20 条，但会话数量无上限，`chat_message` 会持续增长。
4. **同会话并发会覆盖**：`saveAll` 的替换语义下，并发写以后提交者为准。
5. **无 token / 成本的聚合统计**：`TraceAdvisor` 已按调用记录 prompt/completion/total tokens（DEBUG 日志），但仍没有指标、没有按会话/时间段汇总，也没有成本换算。
6. **超时 / 重试不完全**：流式只有 `SseEmitter` 的 120 秒总超时，底层 SDK 的超时与重试仍用默认值，未验证。
7. **同步接口阻塞**：`/chat` 一次占用一个 Servlet 工作线程；`/chat/stream` 已转异步，但两者都无并发压测。
8. **流式无心跳**：长回答经过会主动断空连接的反向代理时，可能被误判断开。
9. **断开不保存半截回答**：客户端断开后，本轮 USER 消息已写入，ASSISTANT 回答不落库；后续追问会看到「只有提问没有回答」的历史。
10. **流式错误暴露原始异常信息**：`error` 事件直接拼接异常 message，可能包含 provider 返回细节；对外部署前需要脱敏。
11. **工具消息不支持持久化**：TOOL 类型会在落库时抛异常，M5 处理。
12. **温度等参数是否生效未单独验证**：只能间接从回答风格判断，不可靠。
13. **结构化抽取无重试 / 修复**：解析失败或全空直接 422，不会用 repair prompt 再问一次。
14. **结构化输出不支持流式**：2.0.2 的 `StreamResponseSpec` 没有 `entity()`；当前只做同步抽取。
15. **抽取无字段级校验**：例如 `age=9999` 会被接受；只有「所有字段为空 → 422」这一条最小校验。
16. **422 响应体不含原因**：与缺口 1 同源，M8 统一错误响应时解决。
17. **提示词模板需重启生效**：模板打包在 jar 内，不支持热更新。
18. **没有写操作工具**：当前两个工具都是只读；副作用工具、人工确认机制未引入。
19. **工具无法按用户隔离**：未使用 `ToolContext` 透传用户 / 会话信息。
20. **没有工具级观测**：只记录整条链路的总耗时 / token，无法区分每次工具调用的耗时与结果大小。
21. **工具 Schema 成本高**：两个工具的 schema 使单次 prompt 增加约 1000 tokens（单次样本）；工具增多时需重新评估。
22. **结果截断未在真机触发**：两个工具返回值都远小于 2000 字符，截断逻辑只有单元测试覆盖。
23. **工具接口不支持流式**：`ToolCallingAdvisor` 支持流式，但本次只接了同步 `/chat/tools`。
24. **RAG 无 rerank / 混合检索 / query 改写**：只有单路向量召回；检索质量主要靠嵌入模型和切片。
25. **向量库只在内存**：`SimpleVectorStore` 启动时重建，没有持久化、增量更新、删除；语料变大后启动成本会上升。
26. **相似度阈值未校准**：`similarity-threshold=0.0`，先接受全部；topK=4 且语料只有 3 篇，命中率高不代表通用检索质量。
27. **RAG 接口无记忆、无流式**：每次请求独立，且只做同步回答。
28. **回答正文不含行内引用**：来源只在 `sources` 数组返回，模型回答里没有 `[1]` 之类标记。
29. **无提示词注入防护**：当前语料是项目自建且可信；接入外部文档前需要过滤/隔离。
30. **onnxruntime 固定 1.20.0**：为绕开本机 JDK 与 1.21.1 的 DLL 兼容问题而降级，属于环境相关技术债，升级时需重测。
31. **评估集偏小**：3 篇语料、10 条问题，只验证了检索链路；生成回答正确率只做了 1 题对照。

## 怎么跑

```bash
# 1. 建库建表（首次或重建时；可重复执行）
mysql -u root -p < sql/schema.sql

# 2. 下载本地嵌入模型（首次；约 91 MB）
mkdir -p models/bge-small-zh-v1.5
curl -L -o models/bge-small-zh-v1.5/model.onnx \
  "https://hf-mirror.com/Xenova/bge-small-zh-v1.5/resolve/main/onnx/model.onnx"
curl -L -o models/bge-small-zh-v1.5/tokenizer.json \
  "https://hf-mirror.com/Xenova/bge-small-zh-v1.5/resolve/main/tokenizer.json"

# 3. 启动
export JAVA_HOME=/e/Java/jdk-21.0.5
export DEEPSEEK_API_KEY=<你的 key>
export MYSQL_PASSWORD=<你的 MySQL 密码>
mvn -f D:/Project/AIProject/polaris-ai/dev/polaris-ai/pom.xml spring-boot:run
```

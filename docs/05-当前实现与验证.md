## 接口

### `GET /api/hello`

连通性检查，不依赖模型。

```bash
curl http://localhost:8103/api/hello
```

```json
{"app":"polaris-ai","message":"Hello, Polaris!"}
```

### `POST /api/chat`

多轮对话。同一个 `conversationId` 共享记忆；记忆窗口最多 20 条消息，超限由 `MessageWindowChatMemory` 裁剪。

请求：

```json
{"message":"我叫 Alice，请记住","conversationId":"11111111-1111-1111-1111-111111111111"}
```

响应：

```json
{"content":"你好，Alice！很高兴认识你。"}
```

错误：

- `message` 为空 → HTTP 400。
- `conversationId` 为空或超过 64 字符 → HTTP 400。
- 模型调用或数据库异常 → HTTP 500。
- 400/500 的响应体都是框架默认格式，**不含具体原因**（`server.error.include-message=never`）：
  ```json
  {"timestamp":"2026-11-07T04:26:47.724Z","status":400,"error":"Bad Request","path":"/api/chat"}
  ```

### `POST /api/chat/stream`

流式对话，SSE。请求体与 `/chat` 相同，校验规则相同；同一 `conversationId` 与同步接口共享记忆。

```bash
printf '{"message":"用三句话介绍你自己","conversationId":"11111111-1111-1111-1111-111111111111"}' > /tmp/polaris-stream.json
curl -N -X POST http://localhost:8103/api/chat/stream \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-stream.json
```

事件：

```
event:delta
data:{"content":"我是"}

event:delta
data:{"content":" Polaris"}

event:done
data:{"conversationId":"11111111-1111-1111-1111-111111111111"}
```

- `delta`：`{"content":"片段"}`，每个非空增量一条。
- `done`：`{"conversationId":"..."}`，正常结束。
- `error`：`{"message":"模型调用失败：..."}`，上游失败。流已开始，HTTP 状态仍是 200。
- 参数不合法 → 流开始前返回 HTTP 400。
- 客户端断开 → 服务端发送失败，取消上游模型调用；已生成的部分回答不写入记忆。

## 实现要点

- `config/ChatClientConfig`：构建 `ChatClient`，注入默认系统提示词和 `MessageChatMemoryAdvisor`；`ChatMemory` 使用 `MessageWindowChatMemory`（默认 20 条），底层仓库为 `JdbcChatMemoryRepository`。
- `chat/ChatController`：校验 `message` / `conversationId`，通过 advisor 参数 `ChatMemory.CONVERSATION_ID` 指定会话。
- `chat/ChatController#stream`：`ChatClient.stream().content()` 拿到 `Flux<String>`，逐片写成 SSE `delta`；正常结束发 `done`，异常发 `error`。`SseEmitter` 超时 120 秒；发送失败（客户端断开）时取消上游订阅。
- 流式记忆依赖 `MessageChatMemoryAdvisor` 的聚合：只有流正常完成才保存 ASSISTANT 消息。
- 序列化使用 Spring Boot 4 自动装配的 Jackson 3（`tools.jackson.databind.ObjectMapper`），不是 Jackson 2。
- `memory/JdbcChatMemoryRepository`：`saveAll` 在一个事务内先删后批量插入，符合接口的「替换整组消息」语义；按 `id` 升序还原消息顺序。
- 消息类型只持久化 USER / ASSISTANT / SYSTEM；遇到 TOOL 直接抛异常，留到 M5。
- 建表不自动执行：启动前手工运行 `sql/schema.sql`。

## 已知缺口

按重要性排列：

1. **无统一错误**：同步接口的 401 / 超时 / 参数错误仍被折叠成 400/500 裸响应；流式接口虽有 `error` 事件，但错误码、分类和可重试性都未统一。
2. **无鉴权**：知道 `conversationId` 就能读写该会话；ID 不是安全边界。
3. **记忆无 TTL / 清理**：单会话最多 20 条，但会话数量无上限，`chat_message` 会持续增长。
4. **同会话并发会覆盖**：`saveAll` 的替换语义下，并发写以后提交者为准。
5. **无 token / 成本记录**：无法回答「这次调用花了多少」；流式路径同样没有 usage 统计。
6. **超时 / 重试不完全**：流式只有 `SseEmitter` 的 120 秒总超时，底层 SDK 的超时与重试仍用默认值，未验证。
7. **同步接口阻塞**：`/chat` 一次占用一个 Servlet 工作线程；`/chat/stream` 已转异步，但两者都无并发压测。
8. **流式无心跳**：长回答经过会主动断空连接的反向代理时，可能被误判断开。
9. **断开不保存半截回答**：客户端断开后，本轮 USER 消息已写入，ASSISTANT 回答不落库；后续追问会看到「只有提问没有回答」的历史。
10. **流式错误暴露原始异常信息**：`error` 事件直接拼接异常 message，可能包含 provider 返回细节；对外部署前需要脱敏。
11. **工具消息不支持持久化**：TOOL 类型会在落库时抛异常，M5 处理。
12. **温度等参数是否生效未单独验证**：只能间接从回答风格判断，不可靠。

## 怎么跑

```bash
# 1. 建库建表（首次或重建时；可重复执行）
mysql -u root -p < sql/schema.sql

# 2. 启动
export JAVA_HOME=/e/Java/jdk-21.0.5
export DEEPSEEK_API_KEY=<你的 key>
export MYSQL_PASSWORD=<你的 MySQL 密码>
mvn -f D:/Project/AIProject/polaris-ai/dev/polaris-ai/pom.xml spring-boot:run
```

验证：

```bash
curl http://localhost:8103/api/hello

printf '{"message":"我叫 Alice，请记住","conversationId":"11111111-1111-1111-1111-111111111111"}' > /tmp/polaris-chat-1.json
curl -X POST http://localhost:8103/api/chat \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-chat-1.json

printf '{"message":"我叫什么？","conversationId":"11111111-1111-1111-1111-111111111111"}' > /tmp/polaris-chat-2.json
curl -X POST http://localhost:8103/api/chat \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-chat-2.json

# 流式：必须加 -N，否则 curl 会缓冲，看不到逐段效果
printf '{"message":"用三句话介绍你自己","conversationId":"11111111-1111-1111-1111-111111111111"}' > /tmp/polaris-stream.json
curl -N -X POST http://localhost:8103/api/chat/stream \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-stream.json
```

> 中文请求体用文件 + `--data-binary`，避免 Windows 终端的 GBK 编码问题。同一 `conversationId` 才有记忆；换 ID 即新会话。

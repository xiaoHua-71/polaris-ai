## 接口

### `GET /api/hello`

连通性检查，不依赖模型。

```bash
curl http://localhost:8103/api/hello
```

```json
{"app":"polaris-ai","message":"Hello, Polaris!"}
```

### `POST /api/chat`

同步对话。**无记忆**：每次请求独立，模型只能看到本次的 `message` 和默认系统提示词。

请求：

```json
{"message":"用一句话介绍你自己"}
```

响应：

```json
{"content":"我是 Polaris，一个简洁、乐于助人的中文 AI 助手。"}
```

错误：

- 空 `message` → HTTP 400，响应体为框架默认错误格式：
  ```json
  {"timestamp":"2026-11-03T14:21:26.120Z","status":400,"error":"Bad Request","path":"/api/chat"}
  ```
  注意：`ResponseStatusException` 里写的「message 不能为空」**没有出现在响应体**（`server.error.include-message` 默认 `never`）。
- 模型调用失败 → HTTP 500，同样是框架默认格式；具体原因只在服务端日志里。

## 实现要点

- `config/ChatClientConfig.java:11`：用自动装配提供的 `ChatClient.Builder` 构建单例 `ChatClient`，注入默认系统提示词「你是 Polaris，一个简洁、乐于助人的中文 AI 助手。」
- `chat/ChatController.java:28`：`chatClient.prompt().user(message).call().content()`，同步阻塞调用。
- 没有自定义 `OpenAiChatModel` / HTTP 客户端；连接参数全部由 starter 自动装配。
- 没有 `ChatMemory`、Advisor、工具、流式、持久化。

## 已知缺口

按重要性排列：

1. **无记忆**：多轮对话不成立；每次请求只带一条用户消息。
2. **无流式**：回答要等完整生成后一次性返回，首 token 延迟不可见。
3. **无统一错误**：401 / 超时 / 参数错误全被折叠成 400/500 裸响应；调用方无法区分。
4. **无超时 / 重试**：完全依赖底层 SDK 默认行为，未验证。
5. **无 token / 成本记录**：无法回答「这次调用花了多少」。
6. **无鉴权**：接口对任何能访问 8103 的人开放。
7. **同步阻塞**：一次对话占用一个 Servlet 工作线程，当前无并发压测。
8. **温度等参数是否生效未单独验证**：只能间接从回答风格判断，不可靠。

## 怎么跑

```bash
export JAVA_HOME=/e/Java/jdk-21.0.5
export DEEPSEEK_API_KEY=<你的 key>   # 或确认已在系统环境变量里
mvn -f D:/Project/AIProject/polaris-ai/dev/polaris-ai/pom.xml spring-boot:run
```

验证：

```bash
curl http://localhost:8103/api/hello
printf '{"message":"用一句话介绍你自己"}' > /tmp/polaris-chat.json
curl -X POST http://localhost:8103/api/chat \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/polaris-chat.json
```

> 中文请求体用文件 + `--data-binary`，避免 Windows 终端的 GBK 编码问题。

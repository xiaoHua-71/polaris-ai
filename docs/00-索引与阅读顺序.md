# Polaris · 文档索引

## 这套文档是什么

Polaris 是一个**学习 / 实验性质**的 Spring AI 项目。这套文档采用「**文档带动实现**」：

> 每个非平凡模块，先写清楚「治哪类病 → Spring AI 官方怎么做 → 本项目怎么落地 → 数据结构与流程 → 边界与坑」，再写代码。

文档的读者是**三个月后的自己**。重点不是描述代码在做什么（读代码更快），而是记录**为什么是这个样子**、**哪些坑已经踩过**、**哪些结论还没验证**。

## 怎么读

第一次接触，按顺序读：

1. [01-项目定位与边界](01-项目定位与边界.md) —— 这个项目为什么存在、不做什么
2. [02-技术栈与版本](02-技术栈与版本.md) —— 版本组合、兼容性依据、升级清单
3. [03-路线图与里程碑](03-路线图与里程碑.md) —— 一共几个阶段、现在在哪、下一步是什么
4. [04-开发与文档约定](04-开发与文档约定.md) —— 包结构、接口约定、配置、提交与文档流程
5. [05-当前实现与验证](05-当前实现与验证.md) —— 已经有什么、怎么跑、验证到了什么程度
6. [06-风险与待验证](06-风险与待验证.md) —— 哪些是实测事实、哪些只是推断

**要改对话功能**：读 [10-对话基础](10-对话基础.md)，再看 [05](05-当前实现与验证.md) 的接口契约。
**要开新模块**：先复制 [模块文档模板](templates/模块文档模板.md)。

## 编号规则

| 编号 | 领域 |
|---|---|
| `0x` | 总览、定位、版本、路线图、约定、当前实现、风险 |
| `1x` | 对话主链路（基础对话、记忆、流式、结构化输出、工具调用） |
| `2x` | RAG 与检索 |
| `3x` | MCP / Agent 扩展 |
| `5x` | 可观测性与工程化 |
| `templates/` | 可复制的文档骨架，不参与编号 |

## 一条维护约定

**实现与文档不一致时，默认文档错了，改文档。** 如果是设计变更，同时把「原设计为什么不成立」写进该模块的「边界与坑」。

过期的文档比没有文档更糟——它会主动误导人。
